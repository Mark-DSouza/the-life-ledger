## Architecture

**LifeOS** is a personal life-tracking dashboard with 8 sections: Fitness, Meals, Sleep, Mental, Personal, Career, Work, and an Overview.

### Stack

- **TanStack Start** (SSR framework) + **TanStack Router** (file-based routing) + **React 19**
- **Tailwind CSS v4** via `@tailwindcss/vite`
- **Supabase** (auth + database)
- **Cloudflare Workers** as the deployment target (`wrangler.jsonc`, `src/server.ts` is the worker entry)
- **Bun** as the package manager and runtime

### Vite config constraint

`vite.config.ts` uses `@lovable.dev/vite-tanstack-config` which already bundles `tanstackStart`, `viteReact`, `tailwindcss`, `tsConfigPaths`, `cloudflare` (build), `componentTagger` (dev), env injection, `@` alias, and deduplication plugins. **Do not manually add any of these** — duplicates break the build.

### Routing

Routes are in `src/routes/`. `src/routeTree.gen.ts` is auto-generated by the TanStack Router plugin — never edit it manually. The router is created in `src/router.tsx` with a shared `QueryClient` passed as context.

### Auth flow

1. Client: `AuthProvider` (`src/lib/auth.tsx`) wraps the app and exposes `useAuth()` — provides `{ session, user, loading, signOut }`.
2. Protected pages: wrap content in `<RequireAuth>` (from `src/components/require-auth.tsx`) which renders `AppShell` and redirects to `/login` if unauthenticated.
3. Server functions: `requireSupabaseAuth` middleware (`src/integrations/supabase/auth-middleware.ts`) validates the Bearer token on every server fn call, returning `{ supabase, userId, claims }` in context.
4. The global `functionMiddleware` in `src/start.ts` (`attachSupabaseAuth`) automatically attaches the session's access token to all `createServerFn` RPC calls from the browser.

### Data persistence pattern

`useUserData<T>(key, seed)` (`src/lib/storage.ts`) is the single hook used by every feature page:

- Calls the `getUserData` server fn on mount to load persisted data from Supabase.
- Falls back to `seed` (the default data constant defined per page) until load resolves or for unauthenticated users.
- Debounces saves back to Supabase at 400 ms after any state change (once initial load is done).

Server fns `getUserData` / `saveUserData` live in `src/lib/user-data.functions.ts`. `saveUserData` validates input with Zod before any DB write; each `key` (fitness, meals, sleep, mental, personal, career, work) has a strict per-key schema.

### Database schema (Supabase)

The data model is weekly (Mon–Sun). Each section has a parent "days" table (one row per user×weekday) and child tables for items ordered by `position`:

| Section              | Tables                                                  |
| -------------------- | ------------------------------------------------------- |
| Fitness              | `fitness_days`, `fitness_lifts`, `fitness_cardio`       |
| Meals                | `meal_days`, `meal_entries`                             |
| Sleep                | `sleep_days`, `sleep_interruptions`                     |
| Mental               | `mental_days`, `mental_actions`                         |
| Personal/Career/Work | `life_goals`, `life_tasks` (shared, filtered by `area`) |

Save strategy for fitness/meals/sleep/mental: upsert the day row (conflict on `user_id,weekday`), then delete+insert child rows. Save strategy for goals/tasks boards: full delete+insert.

### Key shared components

- `AppShell` (`src/components/app-shell.tsx`) — sidebar layout with nav, user info, and sign-out. Desktop sidebar + mobile drawer.
- `RequireAuth` + `PageHeader` (`src/components/require-auth.tsx`) — auth guard that wraps `AppShell`.
- `ExpandableCard` + `Pill` (`src/components/expandable-card.tsx`) — collapsible card used for each day across all feature pages.
- `InlineEdit` (`src/components/inline-edit.tsx`) — auto-sizing inline input that renders as plain text, used everywhere for editable values.
- `src/components/ui/` — shadcn/ui component library; treat these as library files, not application code.

### Environment variables

Both server and client need Supabase credentials:

```
SUPABASE_URL=...                   # server-side (SSR / worker)
SUPABASE_PUBLISHABLE_KEY=...       # server-side
VITE_SUPABASE_URL=...              # client-side (Vite build-time)
VITE_SUPABASE_PUBLISHABLE_KEY=...  # client-side
```

`src/server.ts` is the Cloudflare Worker entry; it wraps TanStack Start's bundled SSR entry and adds branded error handling for h3's swallowed 500s.
